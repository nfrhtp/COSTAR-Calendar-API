COSTAR Calendar API

Read-only JSON access to the COSTAR calendar — daily COSTAR dates, lumas, chromas, lunations, lunar phases, and solar events, 2000–2051.

The COSTAR calendar maps lunar phases, solar events, and Gregorian dates onto cycles of rotunda (25 years), spiral years, quinquennia, lunations, 8-day spiral weeks, and luma/chroma designations. This API serves the same golden dataset that drives the calendar subscription feed. No authentication, no keys — just fetch.

curl https://api.costar.date/v1/today

Endpoints

EndpointReturns
/v1/todayToday's day object, resolved in Pacific Time (the calendar's native zone)
/v1/day/2026-07-21One day
/v1/range/2026-01-01/2026-03-01Array of days (max 400 per request)
/v1/month/2026-07 · /v1/year/2026Calendar-month / Gregorian-year ranges
/v1/events/phases/2026Lunar phase events for a year
/v1/events/solar-terms/2026The 12 major solar terms (incl. solstices/equinoxes)
/v1/events/lunations/2026Lunation starts (new moons) for a year
/v1/events/shenEvery Shen lunation and Shen week in the dataset
/v1/costar/R1/SY1/Red/Gamma/YellowReverse lookup: COSTAR date → Gregorian date(s)
/v1/dataset.csv · /v1/dataset.jsonThe full dataset in bulk
/v1/metaCoverage, dataset version, source checksum

Add ?raw=1 to day/range/month/year endpoints to get the 41 golden-CSV columns verbatim instead of structured JSON.

Day object

Structured responses group the resolved calendar values under costar, the slash-notation transition strings under transitions, and astronomy under phase / solar:

{
  "date": "2026-07-21",
  "costarDate": "R1 SY1 Red Beta Yellow",
  "costar": { "rotundum": 1, "spiralYear": 1, "qLuma": "Alpha",
              "syLuma": "Alpha", "lunation": "Red", "weekLuma": "Beta",
              "dayChroma": "Yellow", "nightLuma": null,
              "weekNumber": 30, "weekdayNumber": 3 },
  "transitions": { "sy": "1", "weekLuma": "Beta", "…": "…" },
  "specials": { "chroma": null, "luma": null },
  "lunationStarting": null,
  "phase": { "dayNumber": 7, "brownLunation": 1281, "lunationNumber": 328,
             "event": { "name": "First Quarter", "number": 2, "timePT": "04:05",
                        "utc": { "weekday": "Tue", "date": "2026-07-21",
                                 "time": "11:05" } } },
  "solar": null,
  "gregorian": { "weekday": "Tuesday", "displayDate": "21 Jul 2026",
                 "dayOfYear": 202, "julian": 2461243, "timezone": "PDT" },
  "meta": { "apiVersion": "v1", "datasetVersion": "2026-07-05" }
}

Reverse lookup uses the resolved (CD) values, which are single-valued every day: the lunation is White or Black (never White/Black), the week luma is Epsilon or Alpha, and Sunday's day chroma is Black. Slash-notation transition values appear inside day payloads, never in URLs.

Stability & versioning

  • /v1 response shapes are frozen; changes are additive only.
  • Calendar data can change by adjudication (rulings on the calendar's rules). Every response carries meta.datasetVersion; compare it to /v1/meta to detect stale caches.
  • This is a free, best-effort service with no uptime guarantee.
